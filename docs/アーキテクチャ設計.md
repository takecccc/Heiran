# アーキテクチャ設計

`Heiran` の構成と、層ごとの責務を定める。実装状況の正は `CMakeLists.txt` の `heiran_core` に登録された
ファイルとする。判断の経緯は [設計判断.md](./設計判断.md) にある。

## 目的

- 複数画像の同期表示を、責務を分離した構造で実装する。
- 表示、設定の読み込み、画像の管理、解析を疎結合に保ち、画面を立てずにテストできる部分を増やす。

## 技術方針

- C++20、Qt 6 Widgets、CMake。Windows と MSVC、Ninja を前提とする。
- アプリケーションは `QMainWindow` ベース。画像の表示面は独立したカスタムビュー。
- 画像の描画は GPU (`QOpenGLWidget` と `GpuImageRenderer`)。選択範囲、カーソル、ラベルなどの重ね描きは `QPainter`。
- 画像の解析は CPU で、解析用バッファの値を使う (GPU には載せない)。

## レイヤ構成

1. UI 層 (`src/ui`)
2. アプリケーション層 (`src/app`)
3. ドメイン層 (`src/domain`)
4. インフラ層 (`src/infra`)

依存の向きは `ui` -> `app` / `domain` / `infra`、`app` -> `domain` / `infra`、`infra` -> `domain`。
`domain` は他の層に依存せず、`QtGui` にも依存しない。

### UI 層

ユーザー操作と画面描画、ウィンドウ、ダイアログ、解析ウィンドウを担う。

- 画面の骨格
  - `MainWindow`: メニュー、ツールバー、ステータスバー、ドック、キー操作を持つ。
  - `ViewerGridWidget`: 複数のセルの配置、同期、ページ送り、アニメーションの進行、共有選択範囲、差分のセルを持つ。
  - `ImageViewWidget`: 1 セルの画像表示、パン、ズーム、マウス位置の通知、差分の設定の帯を持つ。
  - `FileDragController`: 表示面の Ctrl + ドラッグを検出し、元ファイルの URL をコピー操作で OS へ渡す。
  - `ViewerChromeController`: ヘッダーの表示設定と、ナビゲーション非表示時のページ操作を管理する。
- 描画
  - `GpuImageRenderer` (テクスチャ、シェーダ)、`DisplayTransform` (CPU の表示変換。ルーペと差分が使う)、
    `ColorManagement` (色の変換)、`CellOverlayPainter` (選択範囲、カーソル、ラベル)、`CellStatusPainter`
    (空欄、読込中、失敗の表示)、`DisplayLink` (画面の更新に合わせた描き直し)。
- キャッシュ
  - `DecodeScheduler` (非同期の読み込み)、`DecodeCache` (復号結果の LRU、バイト数の予算)、`PrefetchPlanner`
    (先読みの方針)、`TextureBudgetLedger` (GPU テクスチャの予算)、`ThumbnailLoader` / `ThumbnailCache`。
- 解析
  - `AnalysisWindowBase` (閉じても隠すだけ、隠れている間は計算しない)、`HistogramWindow`、`Histogram3DWindow`、
    `DiffWindow`、`ChangeGraphWindow`、`ImageInfoWindow`。集計は `HistogramSeriesBuilder`、`ChangeGraphSeriesBuilder`、
    `DiffRenderer` などの純粋な関数へ分け、`AnalysisResultCache` が結果を取っておく。入力は `AnalysisSampler` が、
    解析用バッファから (回転、反転を戻して) 値を読む。
- セッションの変更
  - `SessionLayoutController` (格子、並べ替え)、`SessionMutationController` (ドロップ、ラベル、割り当て)、
    `DirtyStateController` (未保存の印)。ウィジェットとセッションの間に層を挟まず、セッションを書き換える規則だけを
    UI 非依存の関数へ出している。
- 起動引数の準備
  - `StartupPreparationController` が `.hrn` の読み込みと、画像を直接開くための一覧・セル割り当て・開始ページの計算を行う。
    引数がある場合はワーカーへ値を渡して実行し、UI は準備済みのモデルだけを反映する。
    履歴の更新とウィジェットの操作はワーカーに持たせない。未受領のタスクは controller の破棄時に待つ。
    一覧の準備後、初期ページの復号を起動用 `DecodeScheduler` へ要求する。UI スレッドで作った scheduler を画面側へ渡し、
    完了済みの結果と処理中のジョブを引き継ぐ。受領前の結果は一時保持し、LRU 管理は `DecodeCache` に任せる。
- お気に入り
  - `FavoritesController` がマーク操作、候補ページの選択、一括コピーの UI を持つ。
    `PageNavigationFilter` は元のページ番号とナビゲーション位置を対応付け、永続モデルを変更しない。
    `FavoriteStore` はユーザーデータの読み書き、`FavoriteExporter` は元画像を変更しないコピーを行う。
- そのほか
  - `AppSettings` (アプリ全体の設定)、`AppStyle` (配色と QSS)、`ActionIcons`、`FileOperations`、`ImagePrinter`、
    `AboutDialog`、`SettingsDialog`、`SessionIssueDialog`、`ImageSetManagerDialog`、`PageThumbnailDialog`。

UI 層は、設定ファイルの生のテキストを直接扱わない。

### アプリケーション層

- `ApplicationController`: 起動、`.hrn` の開閉、最近使ったファイル、起動引数の解釈。
  起動時は `prepareStartup` (履歴を変更しない読み込み) と `completeStartup` (受け入れた結果の履歴反映) に分ける。
- `SessionController`: `SessionDocument` (保存形式) と `SessionModel` (実行時のモデル) の変換、画像セットの解決。
- `SessionPathResolver`: glob の展開と `resolvedPaths` の計算。
- `CrashReporter`: 落ちたときのミニダンプ。

### ドメイン層

- `SessionModel` / `SessionDocument`: `.hrn` で定義される全体の状態。`ImageSet` (1 つの画像系列)、`CellConfig` (セルごとの
  設定、差分の指定 `CellDiff` を含む)、`ViewerLayout`。
- `ViewState`: `GlobalViewState` (基準倍率、基準オフセット、現在ページ) と `CellViewState` (同期、パンの差分、倍率、
  ガンマ、回転、反転、白黒反転)、フィットの計算、セル間の座標の写し。
- `ImageTransform`: 回転と反転、表示座標と元画像の座標の写し。
- `ColorSpace`: 原色と輝度の重み。
- `DiffMetrics` / `DiffSettings`: 差分の指標と設定。
- `CellConfigMapping`、`SessionPages`: 設定と状態の対応、ページの対応付け。

### インフラ層

外部のファイルと画像のデコーダを担う。`ImageDecoder` が入口で、形式ごとの読み手へ振り分ける。

- `ImageDecoder`: 拡張子で読み手を選び、`DecodedImage` (表示用の `QImage`、解析用バッファ、元の精度と色モデル、
  色空間、EXIF の向き、ページとフレームの情報) を返す。読み手の一覧は [設計判断.md](./設計判断.md#画像の読み込み)。
- 形式ごとの読み手: `ExrDecoder`、`TiffDecoder`、`AvifDecoder`、`JxlDecoder`、`HdrDecoder`、`TgaDecoder`、`DpxDecoder`、
  `PsdDecoder`、`WebpDecoder`、`ApngDecoder`、`GifStream` (どれも `RawImage` またはフレームの並びを返す)。
- 補助: `AnimationComposer` (フレームの合成)、`CmykConversion`、`EmbeddedColorProfile`、`ExifReader` / `ExifOrientation` /
  `ImageMetadata` (メタデータ)。
- `HrnConfigLoader` / `HrnConfigWriter`: `.hrn` の読み書き。
- `UserDataPaths`: ユーザーデータの基準フォルダー。お気に入り、サムネイルキャッシュ、クラッシュダンプで共有する。

## 主要責務の分離

### 設定の読み込み

- `.hrn` の構文の解釈は `HrnConfigLoader` が担当する。妥当性の確認は、可能な範囲で読み込み時に行う。
- 保存は、内部のモデルから正規化して書き直す。

### 画像系列の管理

- glob の解決、自然順 / 文字列順の並べ替え、ページの位置合わせは `SessionPathResolver` と `SessionPages` が担当する。
- セルへどの画像セットを割り当てるかは `CellConfig` が持つ。

### 表示状態の管理

- 同期の対象で共有する状態は `GlobalViewState`、セル固有の差分は `CellViewState` に持つ。
- 最終の表示位置と倍率は、両者の合成で求める (`final_scale = base_scale * cell.scale`、
  `final_offset = (base_offset + offset_delta) / cell.scale`)。

## 座標系と表示基準

- 画像座標系は左上原点、右が x の正、下が y の正。画像内の位置、選択範囲、マウスの位置、解析の対象の矩形は、この座標で統一する。
- 大きさの異なる画像を並べても、個別倍率の後の表示位置は左上で揃える。

## パン・ズームの基準

- パンは、ドラッグ開始時点のマウス位置を基準にオフセットを更新する。
- ズームは、ホイールを回したときに指している画像上の位置を固定点にする。ズームの前後で、マウス直下の画像座標が、できるだけ
  同じ画面位置に残るよう、`base_offset` と `offset_delta` を計算し直す。
- `base_offset` と `offset_delta` は、個別倍率の適用前の正規化座標で持つ。最終の表示では `cell.scale` で割り戻す。
  ズームの固定点は、操作したセルの画像座標を `image_position * cell.scale` で正規化座標へ変換して使い、有効なオフセットは
  `base_offset + offset_delta` として扱う。
- ズームは、同期の有無に関わらず `GlobalViewState` を更新し、全セルへ反映する。パンは、同期有効のセルなら `GlobalViewState`、
  同期無効のセルならそのセルの `CellViewState` だけを更新する。

## 画像の描画

- `ImageViewWidget` は、最終の表示パラメータを受け取って描画する。
- 解析用バッファを持つ画像 (16bit 整数、half、float) は `RGBA16F` (16bit 整数は `RGBA16`) のテクスチャで載せる。8bit は表示用の
  `QImage` を載せる。回転、反転、露出、ガンマ、チャネル、白黒反転、色の変換は、フラグメントシェーダで行う。縮小はミップマップ。
- 表示用の `QImage` は、要求されたときだけ作る (画面の描画は必要としない)。

## 解析

- 解析の対象 (全セルの画像、解析用バッファ、選択範囲) は `ViewerGridWidget` が `AnalysisImage` の並びとして渡す。
  解析ウィンドウは、これを受け取って自分で集計する。
- 解析は読み取り専用で、解析用バッファを変更しない。値は、表示用の画像ではなく解析用バッファから読む。
- 共有選択範囲は、選択を始めたセルを基準にした画像座標で持ち、他のセルへは各セルの `FinalViewState` から再投影する。
- ヒストグラムの横軸は、全セルで共通。詳細は [解析機能設計.md](./解析機能設計.md)。

## 同期表示モデル

同期表示の状態は 3 つで持つ。

1. `GlobalViewState`: `base_scale`、`base_offset`、`current_page`。
2. `CellViewState`: `sync_enabled`、`offset_delta`、`scale`、`gamma`、`rotation`、`flip_x`、`flip_y`、`invert`。
   (チャネルはセルごとの別の状態として持ち、`.hrn` の `ch` に対応する。)
3. 共有選択範囲: `selection_rect` と可視状態。どのセルで操作しても、全セルへ反映する。

同期状態の詳細な更新規則は [表示状態仕様.md](./表示状態仕様.md) に記載する。

## データフロー

`.hrn` を開いたときの基本のフローは次のとおり。

1. 起動引数かメニューで `.hrn` のパスを受け取る (`ApplicationController`)。
2. `SessionController` が `HrnConfigLoader` を呼び、`SessionDocument` を作る。
3. `SessionPathResolver` が各 `path` を解決し、ファイルの一覧を作る。
4. `SessionModel` を作り、`ViewerGridWidget` が、各セルへ状態を反映する。
5. `DecodeScheduler` が、現在のページの画像を、続いて前後のページを読み込み、`DecodeCache` が復号結果を持つ。
6. 結果が届いたら、セルが画像を組み立て、フィットが保留されていれば適用する。差分のセルは、元になるセルの画像が揃ったら作る。

画像を直接開いたときは、同じ画像のフォルダを画像セットとして扱い、枚数に合う格子を作って、`.hrn` と同じ経路へ入れる。

## ディレクトリ構成

```text
Heiran/
  CMakeLists.txt
  vcpkg.json
  src/        app / domain / infra / ui
  include/    heiran/<layer>/ (公開ヘッダー)
  tests/
  tools/      開発用の計測、見本の生成、検証の道具
  scripts/    ビルド、テスト、実行、配布の PowerShell
  resources/  アイコン、インストーラ、関連付けの説明、ライセンス全文
  docs/       仕様と設計
  examples/   見本の画像と .hrn
```

## 非機能方針

- UI の応答性を保つため、画像の読み込みと重い解析は、非同期または並列にする。
- 解析用バッファ (元の精度) と、表示用の画像、GPU のテクスチャを分け、演算の精度と表示の速さを両立する。
- テストしやすくするため、設定の読み込み、glob の解決、同期状態の計算、解析の集計は、UI に依存しない形にする。
- キャッシュは、復号結果 (CPU) を既定 1 GiB、GPU のテクスチャを既定 2 GiB のソフト上限とする (どちらも設定で変えられる)。
  詳細は [画像表示設計.md](./画像表示設計.md)。

## 拡張の方針

- 外部プラグインの API は、まだ固定しない。内蔵の解析機能とフィルタ機能の境界が安定してから判断する (経緯は
  [設計判断.md](./設計判断.md#外部プラグインは作らない-当面))。
- 描画のバックエンドを `QRhiWidget` へ移す場合も、次の責務は変えない: `.hrn` の読み込みと `SessionModel`、
  `GlobalViewState` / `CellViewState`、画像とページの対応付け、解析が参照する解析用バッファ。
