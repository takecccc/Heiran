# 画像表示設計

`Heiran` の画像の表示、キャッシュ、描画の方針を定める。判断の経緯は [設計判断.md](./設計判断.md) にある。

## 異サイズ画像の表示基準

- 個別倍率の適用後も、表示の基準位置は左上とする。
- 画像の中心合わせは行わない。
- 解像度の異なる画像の比較では、左上を基準に、同じ画像座標が同じ比較の基準になる。

## データの持ち方

画像は次の 3 つの形で持つ。

1. **元ファイル**: 永続的には保持せず、必要なときに `ImageDecoder` が読み込む。形式ごとの読み手は
   [設計判断.md](./設計判断.md#画像の読み込み) を参照。
2. **解析用バッファ**: 表示、解析、画素値の表示の基準になるデータ。元ファイルの画素の精度
   (`uint8`、`uint16`、`half`、`float`) のまま持ち、`float32` へは演算のときに変換する。消費側は、保持している精度を
   意識せず、`float` を返すアクセサ経由で読む。Qt で読む 8bit の PNG / JPEG のように、表示用の画像がそのまま元データの
   場合は、別に持たない。
3. **GPU のテクスチャ**: 画面へ出すためのもの。解析用バッファを持つ画像は `RGBA16F` (16bit 整数は `RGBA16`) で、8bit は表示用の
   `QImage` から載せる。縮小はテクスチャのミップマップに任せる。

表示用の `QImage` (露出などを掛け、0.0-1.0 に収めた 8bit) は、**要求されたときだけ作る**。画面の描画は必要としない。
ルーペ、差分の重ね合わせ、クリップボードへのコピーなどが使う。**画素値の表示と解析は、必ず解析用バッファから行い、
表示用の画像を入力に使わない。**

## 表示の変換

表示のとき、次の順で変換する (式は `ColorManagement.cpp` に 1 つ置き、シェーダはそれを写す。CPU の経路もある)。

1. 元の値を、元画像の色空間の伝達関数で、線形光へ戻す。
2. 原色を、表示先の色空間へ移す。
3. 露出を掛ける (`2^EV`)。
4. 表示先の伝達関数で符号化する。
5. 利用者が指定したガンマ、白黒反転。

- 色空間が分からない、または色管理が無効なときは、1. 2. 4. を省き、符号化された値へ露出を掛ける。
- 行列と曲線で表せない色空間 (LUT を持つ ICC プロファイル、PQ、HLG) は、3 次元の対応表 (刻み 33) をシェーダで引く。
- 1 つのチャネルだけを出すときは、原色を移さない (曲線は当てる)。
- 回転と反転は、テクスチャ座標側で行う。

### 色空間の決め方

優先順位は、`.hrn` の指定 (`color_space`、`icc_profile`) > 埋め込みの ICC > 形式ごとの補助的な申告 > 形式の既定。
形式の既定は、浮動小数で持つ形式 (EXR、HDR) が線形光、整数形式が sRGB。表示先は、画面に割り当てられたプロファイル
(既定)、sRGB 固定、ICC ファイルの指定から選ぶ。

### 表示の露出調整

- 浮動小数の画像は 1.0 を超える値を持ちうる。表示は 0.0-1.0 に収まるため、そのままでは白く潰れて確認できない。
  露出を段数 (EV) で指定し、`2^EV` を掛けてから丸める。
- 露出は**表示だけ**に掛ける。画素値、ヒストグラム、差分は、解析用バッファの値をそのまま使う。
- 露出は全セルで共通とする (セルごとに変えると、比較の基準が揃わない)。
- 露出は、セッションにも、アプリ全体の設定にも保存しない。表示中の一時的な調整として扱う。
- 解析用バッファを持たない 8bit 画像では、丸め済みの値に掛ける。1.0 を超える情報が残っていないため、明るくしても
  白飛びは復元しない。

### 補間

拡大は `Nearest` / `Smooth`、縮小は `Area` / `Nearest` を、アプリ全体の設定で選ぶ。既定は、拡大が `Nearest` (画素の境界を
そのまま確認できる)、縮小が `Area` (ミップマップ。パン時にちらつかない)。

## キャッシュ戦略

### 復号キャッシュ (`DecodeCache`)

- 復号結果を LRU で持つ。上限は**バイト数のソフト上限**で、既定は `1024 MiB` (設定で `64` から `65536 MiB`。環境変数
  `HEIRAN_DECODE_CACHE_BUDGET_MB` が設定より優先)。上限は、`.hrn` ではなく、アプリ全体の設定に置く (実行環境のメモリ量に依存し、
  同じ `.hrn` を別の PC で開いたとき、不適切になりうる)。
- 鍵は、ファイルのパス、EXIF の向きを適用するか、ページの番号。
- 予算を超えたときの破棄の順:
  1. 現在のページ以外で、解析用バッファを持ち、保持範囲 (現在のページと前後 1 ページ) の外にあるもの
  2. 現在のページ以外
  3. 現在のページ
  同じ順位の中では、最後に使った時刻の古いものから。保持範囲は、**予算を超えたときに最初に捨てる候補**を表すだけで、
  範囲の外だからといって、予算に余裕があるのに捨てることはしない。
- 表示中のアニメーションは、キャッシュではなく、セルが自分で抱える (追い出されて再生が止まらないように)。

### 先読み (`PrefetchPlanner`)

- 先読みの距離は、**予算に何ページ入るか**から決める (入りきらない分を読んでも、届いたそばから捨てられる)。1 ページも入らない
  場合でも、隣までは読む。セルごとに別の画像を出すときは、1 ページが複数のエントリを使う。
- 読む順は、現在のページに近い側から交互。
- アニメーションを見せている間と、読み込み中のセルがある間は、先読みしない。

### GPU テクスチャの予算 (`TextureBudgetLedger`)

- 上限は、**全セルの合計**に掛ける (既定 `2048 MiB`。設定と環境変数 `HEIRAN_GPU_TEXTURE_BUDGET_MB`)。溢れたら、全セルを通して、
  最も使われていないものから捨てる。描いているものは捨てない。
- 鍵は画素データの同一性 (復号キャッシュと同じ考え方)。表示変換 (ガンマ、回転など) が変わってもテクスチャは作り直さない。

### 非同期の読み込み

- 読み込みは UI のスレッドから分離する。同じ鍵への同時の要求は 1 件に束ね、ページを替えて不要になった要求は、結果を適用する前に、
  世代番号を比べて捨てる。セルは、最新のセッションと表示状態に合う結果だけを受け取る。
- 優先順位: (1) 現在のページで、表示中のセルに要る画像、(2) 現在のページの他のセル、(3) 前後のページの先読み、
  (4) 再読込と再試行。実行中のタスクの強制中断はせず、結果の適用前の世代チェックで無効にする。同時のデコード数は、CPU の数。

### 実測の見方

- 性能の数字は **Release** 構成で測る。内訳 (どこで時間を使うか) を測ってから手を入れる。
- 計測の道具: `heiran_decode_benchmark` (復号。全画素のチェックサムも出す)、`heiran_interaction_benchmark` (パン、ズーム、
  hover、ページ送り、起動)、環境変数 `HEIRAN_PROFILE_PAN` / `HEIRAN_PROFILE_LOAD` / `HEIRAN_TRACE_MEMORY`。
  [AGENTS.md](../AGENTS.md) に手順がある。

## 描画

### ホイールでのページ切り替え

- **決定**: `PageWheelController` が Alt + ホイールの判別と回転量の端数を持ち、キャンバスはページ移動の要求を signal で送る。
  `ViewerGridWidget` は既存のページ指定の入口で移動し、複数ノッチでも途中のページの読み込みを開始しない。
- **理由**: 細かな入力ごとにページを送ることを避け、ズーム操作と区別する。画像の有無によらず操作できるよう、画像の存在確認より先に処理する。
- **見直す条件**: 回転量を持たないタッチパッドのピクセルスクロールでもページを送りたい場合。

### 初回フィットの適用時期

- **決定**: 非表示の間はフィット要求を保留し、`ViewerGridWidget` の表示イベント後にキュー経由で適用する。
  読み込み中なら保留を続け、完了時に適用する。適用した描画面の大きさを、以後のリサイズ追従の基準として記録する。
- **理由**: 起動引数の画像がウィンドウ表示より先に読み込まれると、表示前の暫定サイズでフィットが完了してしまう。
  表示と読み込みの両方を待つことで、処理の順序にかかわらず実際の描画面へ合わせる。
- **見直す条件**: 非表示のまま表示状態を確定する用途を追加するとき。

### 描画の順序

- 画像は `GpuImageRenderer` が、`QOpenGLWidget` の上に描く。選択範囲、カーソル、ラベル、セルの状態は、その上に `QPainter` で重ねる
  (GL の描画を先に済ませてから `QPainter` を使う)。
- 透過の下地は、フラグメントシェーダの中で合成する。背景は GL 側で塗る。
  - **決定**: `TransparencyBackground` に単色 / 市松模様と各色を持ち、設定から各セルとルーペへ渡す。
    市松模様の升目は 8 論理ピクセルで、各描画面の左上を原点とする。拡大、移動、回転で模様を動かさず、画像の矩形内だけに合成する。
    背景は画像の色変換・ガンマ・反転の対象外とし、画素値、解析、コピーする画像には含めない。
  - **理由**: 透過の境界を同じ条件で比較でき、拡大中も背景の升目で画像の画素を誤認しない。余白の暗さは画像の透過と別に保つ。
  - **見直す条件**: 升目の大きさや、セッションごとの背景指定が必要になったとき。
- パンのときは、差分のスクロールを使わず、毎回全面を描き直す。描き直しは、画面の更新 (vblank) に合わせる (`DisplayLink`)。
  合図が来ない環境では、更新間隔で時間刻みにする。
- GPU の出力が CPU の実装と一致することを、オフスクリーンのフレームバッファへ描いて比べるテストで固定している (許容差 2)。
- 描画のバックエンドを `QRhiWidget` へ移す場合も、次の責務は変えない: `.hrn` の読み込みとページの対応付け、解析用バッファの保持、
  解析が参照する画素データの供給、キャッシュの上限管理と先読みの順序。
