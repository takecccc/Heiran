MSVC 14.51 / Qt 6.11.1 の手元の環境で測ったもの。

## 全体の方針

### 画面は QWidget、描画は QOpenGLWidget

- **決定**: GUI は Qt Widgets (`QMainWindow` + 独立したカスタムビュー)。画像の描画だけ
  `QOpenGLWidget` 上の `GpuImageRenderer`、選択範囲やカーソルなどの重ね描きは `QPainter`。
- **理由**: 画像表示、同期パン / ズーム、解析 UI が中心のデスクトップツールで、アニメーション主体
  ではないため、QML より Widgets が合う。GPU 描画は `QRhiWidget` も候補だったが、シェーダの事前
  コンパイル (`qsb`) をビルドへ入れる変更が大きく、表示を壊すと確認そのものができなくなる。
  変更範囲の小さい `QOpenGLWidget` を選んだ。
- **見直す条件**: macOS の OpenGL 非推奨が問題になったとき (`QRhiWidget` へ移す)。

### 層の分け方

- **決定**: `app` / `ui` / `domain` / `infra` の 4 層。`domain` は Qt の GUI (`QtGui`) に依存しない。
  座標の写し、輝度の重み、差分の指標、セッションのモデルは `domain`。
- **理由**: 座標変換と同期は挙動の中核で、画面を立てずにテストしたい。`QColorSpace` などの `QtGui` の
  型を `domain` へ持ち込むと依存が崩れるため、`.hrn` の色空間は文字列のまま持ち、解決は `ui` で行う。
- **補足**: 設計時にあった `ViewerController` / `AnalysisController` / `PluginRegistry` は作らなかった。
  表示状態は `ViewerGridWidget` が持ち、セッションを書き換える規則だけを UI 非依存の関数
  (`SessionLayoutController` など) へ出した。解析ウィンドウは `AnalysisWindowBase` を通じて対象の
  並びを受け取り、自分で集計する。調停する層は要らなかった。
- **方針**: 切り出しは目的ではなく、確かめられる形にするための手段。切り出したら、そのテストを書く。
  (テストが 1 件も無いまま切り出しただけのクラスがあった。)

### 外部プラグインは作らない (当面)

- **決定**: 解析プラグインと画像フィルタプラグインは別の仕組みにする。内蔵の解析機能が安定するまで、
  外部 ABI は固定しない。
- **理由**: 解析は読み取り中心、フィルタは画素変換を伴い、責務と性能要件が違う。
- **見直す条件**: 内蔵の解析とフィルタの境界が安定したとき。

### ライセンス

- **決定**: Apache-2.0。依存のライセンス表記は `THIRD_PARTY_NOTICES.txt` に集め、スクリプトで生成する。
  Qt は LGPL-3.0 のため、**動的リンクのまま、DLL を入れ替えられる形で配布する**。
- **理由**: MIT より特許の許諾が明示され、長期保守や外部からの貢献を見込める。

## 設定ファイル (.hrn)

- **形式**: コメントを書ける JSON5 相当のサブセット。拡張子は `.hrn`。人が編集する前提なので、
  純粋な JSON より、`//` コメントと末尾のカンマを許す JSON5 に寄せた。YAML は解釈の揺れが大きく、
  INI は配列と階層が弱いため避けた。`.hrn` は短く、OS の関連付けにも向く。
- **`format_version`**: 解釈の前提が変わるため、他の検証より先に確かめる。未来の版は安全のため失敗にする。
- **検証**: 最初の問題で打ち切らず、項目単位で集約する (上限 20 件、超えた分は要約へ)。人が直すたびに
  読み直して次の問題を知る往復を避けるため。問題は `Error` と `Warning` に分ける。既定値へ読み替えても
  意図が大きく変わらないもの (範囲外の `rotation`、未知の `ch`、存在しない `image` の参照、不正な `diff`) は
  警告で続行する。既定値へ読み替えると意図と違う結果になるもの (`format_version`、必須キーの欠落、
  セル数の超過) だけをエラーにする。位置は `cells[1].rotation` の形で示す。
- **保存**: UTF-8 / LF / スペース 2 つ / 安定したキー順で、内部モデルから作り直す。元のコメントは保たない。
  未知のキーも保たない。
- **保存する状態と、しない状態**: セルごとの表示状態 (倍率、ガンマ、回転、反転、白黒反転、チャネル、同期、
  差分の指定) は `.hrn` に保存する。パン、ズーム、現在ページ、共有選択範囲、露出は一時状態で、保存せず、
  未保存の印 (dirty) にも含めない。次回に暗い露出のまま復元されると原因が分かりにくい。
- **アプリ全体の設定は `.hrn` に置かない**: 表示単位、補間、フィット、キャッシュ上限、配色、カーソルの描き方などは
  利用者の見方に属し、実行環境 (メモリ量など) にも依存する。`QSettings` に保存し、「最近使った `.hrn`」も同じ。
  別の PC で同じ `.hrn` を開いたとき、不適切な上限が付いてくるのを避ける。
- **色空間は `images[]` に置く** (`cells[]` には置かない): 画素データの性質であり、同じ画像を 2 つのセルへ
  出したときに別の色空間になるのは意味をなさない。`color_space` (名前) と `icc_profile` (ファイル) は別の項目にし、
  `icc_profile` を優先する。`.hrn` の指定は埋め込みより強い (埋め込みが誤っている画像を、設定側で正せる)。
- **画像セット**: 1 つの `images[]` が glob で複数のファイル (ページ) を持つ。ドロップしたファイルを現在のページへ
  合わせるため、`pageOffset` を持つ (表示ページ `p` は `resolvedPaths[p - pageOffset]`)。負になる分は全画像セットを
  平行移動して 0 に揃える。
- **読み込みの失敗**: アプリは閉じず、空のウィンドウを残して、別のファイルを開く導線と最近使った一覧を出す。
  個別の画像の失敗は、セル単位のエラー表示と再読込で扱う。

## 表示状態と座標

- **座標系**: 画像は左上原点、x は右、y は下が正。異なる大きさの画像も、個別倍率の後の表示位置は左上で揃える。
- **同期**: ページ番号とズームは全セルで共有する (同期を切ったセルでズームしても全体を更新する)。同期を切ったセルの
  パンは、基準との差分 (`offsetDelta`) として持つ。同期へ戻しても差分は捨てない。位置合わせのために付けた差分は、
  このツールの中心的な機能で、ページ送りで消えると使えない。
- **最終倍率** = 基準倍率 x 個別倍率。パンは個別倍率の適用前の正規化座標で持ち、ドラッグ量は基準倍率で割る。
  ズームの固定点は `baseOffset + offsetDelta` を有効なオフセットとして扱う (そうしないとマウス直下の点が固定できない)。
- **回転と反転**: 回転は 90 度単位で、回転の後に左右 / 上下の反転。EXIF の向きは、利用者の回転と反転より先に
  適用する。適用するかは画像ごとに切り替えられる (既定は適用)。
- **選択範囲**: 共有で、基準にしたセルの画像座標で持ち、他のセルへは現在の表示状態から再投影する (倍率の補正だけでは
  位置がずれる)。内部では半開区間。作るのは `Shift` + ドラッグ (左ドラッグのパンと衝突しないため)、解除は `Esc`。
  セル間の座標の写しは `domain` にあり、選択範囲、カーソルの同期、解析対象の切り出しが使う。
- **フィット**: 基準倍率は、全ての対象が収まる値 (最も制約の強い対象に合わせる)。そうしないと、大きさの違う画像を
  並べたときに他のセルで画像が切れ、比較の目的に反する。基準オフセットは、制約になった対象を中央に置く位置。
  画像は非同期で読み込まれるため、フィットは保留を立てておき、**対象が揃った時点**で適用する。読み込み済みの
  ページへ移るときは通知が来ないので、ページを替えた側でも適用する。画像を直接開いたときは、設定に関わらず
  フィットする (4K を等倍で出すと隅しか見えない)。
- **補間**: 拡大は `Nearest` / `Smooth`、縮小は `Area` / `Nearest`。`QPainter` は双三次補間を持たず、`Smooth` は
  双線形のため、要件の「BICUBIC」ではなく実態に合わせて `Smooth` とした。既定は拡大 `Nearest` (画素の境界が
  見える) と縮小 `Area` (ちらつかない)。
- **ラベル**: 既定では出さない (1 枚を見るだけなら、名前を重ねない方が見やすい)。`{filesize}` `{width}` `{height}`
  を展開できる。

## 画像の読み込み

### 形式ごとの読み手

| 形式 | 読み手 | 備考 |
| --- | --- | --- |
| PNG | libspng (失敗したら Qt へ退避) | Qt の約 2 倍速い。16bit は `RGBA16` で読む |
| JPEG / BMP / GIF | Qt (`QImageReader`) | GIF のアニメーションは自前の逐次合成 |
| APNG / WebP | 自前 (フレームの切り出し) + libwebp | 標準の Qt に WebP は無い |
| EXR | OpenEXR を直接 | パートをページとして扱う |
| TIFF | libtiff を直接 | 8 / 16bit 整数、half、float32、CMYK、複数ページ |
| AVIF | libavif (dav1d) | |
| JPEG XL | libjxl | |
| HDR / TGA / DPX / PSD | 自前 | `RawImage` を返す |

- **決定**: 形式ごとに、最も合う読み手を使う。**失敗しても別の読み手へは退避しない** (自前の復号器は、
  読めない理由をそのまま出す)。PNG だけ、libspng が失敗したら Qt へ退避する。
- **OpenImageIO は使わない**。目的は、依存の軽量化 (配布の DLL が 25 から 13 MB へ)、
  ビルド時間 (再ビルドだけで 8 分)、挙動の制御。OpenImageIO は、依存先が黙って無効になる (JPEG XL の機能が、
  見つけられないまま無効になり、`.jxl` が「読み手が無い」と言われた) など、中で何が起きているか分からなくなる
  問題があった。置き換えの検証は、**OpenImageIO を基準にして画素まで突き合わせる**形で行い (これで DPX の詰め方が
  「語の下位のビットから」だと分かった)、その後、別の書き手 (ImageMagick、ffmpeg) で作ったファイルの確認に
  移した (`tools/generate_cross_writer_samples.py`)。
- **Wuffs と libspng の比較**: 4K PNG の Release での比較では、Wuffs は Qt と同等で優位が無く (16bit PNG にも非対応)、
  libspng は Qt の約 2 倍速かった (Debug での最初の計測は誤りだった)。libspng を既定にし、Wuffs は外した。
  速度で決める判断は **Release で測り、全画素のチェックサムが一致することを確かめてから**行う。
- **PSD**: 合成済みの画像 (互換性を最大にして保存したもの) を読む。レイヤーの合成はしない。8 / 16 / 32bit、
  グレー、RGB、CMYK、RLE。ZIP 圧縮と PSB は未対応。
- **CMYK (PSD と TIFF)**: 埋め込みの CMYK 用 ICC プロファイルがあれば Little CMS で sRGB へ変換する (相対的な色度、
  黒点補正)。無い、壊れている場合は、素朴な式 (R = (1 - C)(1 - K)) へ退避する。出力は sRGB のため、CMYK の
  プロファイルは出力へ付けない (付けると RGB の画素へ CMYK のプロファイルを当ててしまう)。
- **EXIF の向き、埋め込みの色プロファイル、メタデータ**: backend ごとにではなく、1 か所 (`ImageDecoder::decode`) で、
  復号の後にファイルを読み直して取る (backend ごとに書くと、退避の経路で漏れる)。EXIF は自前の読み手で、向きの
  タグだけでなく、画像情報ウィンドウに出す項目を読む。`QImageReader::transformation()` は常に 0 を返すため、
  Qt に頼れない。Qt は向きを実際には適用するが、報告しない。
- **間引きデコードは、ビューアの経路では使わない**。PNG では、`QImageReader::setScaledSize()` が全行を読んでから縮める
  だけで、libspng より遅い。JPEG では DCT の段階で間引けて速いが、現在のページ (画素値の表示のため) も、先読み
  (ページ送りを速くするため) も元の解像度が要る。低い解像度を先に出して後で差し替える案も、比較ビューアでは
  見えているものが揃わないため採らない。サムネイル一覧だけは使う (低い解像度で足りる、画素値を答えない、枚数が多い)。
  ただし形式ごとに最も速い経路が違う (PNG は libspng で読んでから縮めるほうが速い)。
- **HEIC は対象外**: (1) HEVC の特許プールがあり、復号器の同梱でライセンスが要りうる (libde265 の許諾はソースの使用であって、
  特許の許諾ではない)。(2) vcpkg の libheif は HEVC の復号器 (LGPL) を必須で、既定の機能で GPL の x265 まで引き込む。
  (3) iPhone の HEIC は構成が複雑で、攻撃面も大きい。AVIF は libavif で別に読めるため、libheif は入れない。
  **見直す条件**: 必要になったら、同梱せず、Windows の WIC (HEIF 画像拡張) を呼ぶ。
- **IFF / SGI / PIC は対象外**: 需要が無く、読み手を書く費用に見合わない。
- **AVIF / JPEG XL / アニメーション**: アニメーションは先頭の 1 コマだけ。HDR (PQ / HLG) は申告どおりに持ち、
  トーンマッピングはしない。10bit 以上の AVIF と向き (`irot` / `imir`) は、見本を作れず未確認。

### 非同期の読み込み

- 読み込みは、現在のページ > 同じページの他のセル > 前後のページの先読み、の順。`DecodeScheduler` のワーカーは
  CPU の数だけで、完了は signal/slot で通知する (受け側の破棄時に Qt が接続を切るため、寿命の保証がフレームワーク側に移る)。
- キャッシュの鍵は、ファイルのパスだけでなく **EXIF の向きを適用するか**と、ページの番号を含める (別の設定で
  同じファイルを参照したとき、誤った結果を再利用しないため)。
- 「初回の読み込みが遅い」と感じたときは、先読みの範囲を広げる前に測る。最初の 1 枚は窓が出る時点でもう出来ており、
  律速は **OpenGL コンテキストの生成** (約 700 ms、画像の大きさや枚数に関係せず、Qt の backend の選択でも変わらない)。

## ファイルの中の画像 (ページとフレーム)

- **決定**: ページ (TIFF、EXR のパート) とフレーム (GIF、WebP、APNG) を**別の軸**にする。ファイルの連番
  (`currentPage`) とは別に、ファイルの中の軸 (`subImageIndex`) を持ち、**全セルで共有する**。
- **理由**: 性質が違う。ページは独立した画像で、手でめくる。フレームは時間の流れで、再生とコマ送りをする。1 つの軸に
  混ぜると、数百コマのアニメーションがページ一覧を埋め、ファイルの連番 (比較の主役) とコマ送りも区別できなくなる。
- **範囲外の扱い**: アニメーションは巻き戻る (時間は輪になる)。ページは最後のページで止まる (足りない側が空になるより
  比べやすい)。
- **再生**: 画像を直接開いたら自動で再生し、`.hrn` は止めたまま始める (比較が目的で、フレームを合わせて見る)。
  手でコマ送りしたら再生を止める。表示時間が 0 や 10 ms 以下のフレームは 100 ms にする (ブラウザと同じ)。複数のセルの
  進め方は `Auto` (フレーム数が同じなら同期、違えば独立) / `Locked` / `Independent` から選べる。
- **復号の仕方を種類で変える**: フレームは最初に全部読む。ページは指定した 1 つだけを読む (大きなページを何枚も持つ TIFF を
  全部読むと、メモリを使い切る)。
- **大きなアニメーション**: 展開後の大きさ (幅 x 高さ x 4 x フレーム数) が境目 (既定 128 MiB、設定で変えられる) を超える
  APNG / WebP は、**圧縮したまま持ち、要るフレームだけを順に作る** (逐次展開)。キャンバスの写しを一定の間隔で持ち、
  コマ戻しや飛び越しは、最も近い写しから作り直す。APNG の差分を持つ案は採らない (実物は毎回、全面を置き換える作りで、
  差分にしても展開した画素を持つことは変わらず、メモリは減らない)。展開後の大きさは、画素を読まずに、ヘッダーから見積もる。
  実測で、約 700 MB が約 190 MB になり、再生は詰まらなかった。
- **GIF**: 先頭から順にしか復号できない。境目を超えるものは、**再生しながら、合成済みのフレームを zstd (レベル 1) で
  可逆に圧縮して貯める** (非可逆は画素値を変えるため使えない)。LZ4 ではなく zstd にしたのは、実測で復号の速さがほぼ同じで、
  圧縮率が 1.4 から 2.5 倍良かったため。貯める量の上限は 512 MiB。超えたら先頭から復号し直す (遅くなるだけで結果は同じ)。
- **セルが、いま見せているファイルの結果を自分で抱える**。キャッシュは速さのためのもので、表示中のものの持ち主にしない。
  1 つで予算の大半を使うアニメーションが追い出されて、再生が止まる (交互に動いて見える) 不具合があった。
  アニメーションを見せている間は先読みしない。
- **テストの見本は、テストの中で組み立てる** (外部のツールに頼らない)。GIF は LZW を画素 2 つごとの clear で組み、
  TIFF は非圧縮の IFD を並べ、WebP は libwebp のエンコーダを使う。逐次展開が全展開と画素まで一致することを、
  前進、後退、飛び越し、折り返しの順で確かめる。

## 色の扱い

- **変換の engine**: Qt の `QColorSpace` / `QColorTransform`。ただし、**レンダリングインテントと黒点補正は Qt では
  選べない**ため、3 次元の対応表を組む部分にだけ Little CMS (lcms2) を使う。lcms2 が無ければ Qt の変換へ退避する。
  OpenColorIO は足さない。
- **申告の強さ**: ICC > 形式ごとの補助的な申告 (PNG の `sRGB` や `cHRM` + `gAMA`) > 形式の既定。既定は、浮動小数で
  持つ形式 (EXR、HDR) は線形光、整数形式は sRGB。どちらも慣習であって保証ではないため、`.hrn` で上書きできる。
- **表示の順序**: 元の値 -> 線形光 -> 原色の変換 -> **露出** -> 表示用の符号化 -> 利用者のガンマ -> 白黒反転。
  - 露出は線形光で当てる (段数は光量の倍率。sRGB の 0.5 に 2 倍を掛けて戻すと 0.6858 で、符号化された値へそのまま掛けた
    1.0 とは別物)。
  - 利用者のガンマは、色管理の後に残す。色管理は「正しく出す」、ガンマは「見やすくする」で、混ぜると、どちらを動かして
    いるか分からなくなる。
  - 1 つのチャネルだけを出すときは、原色を移さない (値を並べ替えた偽色であり、色ではない)。曲線は当てる。
  - 式は `ColorManagement.cpp` に 1 つ置き、GLSL はそれを写す。GPU と CPU の一致を、テストで固定する (許容差 2)。
- **表示先**: 画面に割り当てられたプロファイル (既定)、sRGB 固定、ICC ファイルの指定から選べる。画面は、装置の配置と
  大きさで突き合わせる (`QScreen::name()` は GDI の装置名ではない)。読めなければ sRGB へ退避して表示は続ける。
- **行列で表せない色空間** (LUT を持つ ICC、PQ、HLG): 復号時に CPU で正規化せず (元の値を書き換えると、解析が元の値を
  読むという契約が崩れる)、**3 次元の対応表**へ焼いてシェーダで引く。刻みは 33 (組み立ては 3 ms 程度)。出力は表示用の
  線形光で、行列の経路と順序をそろえる。テクセルの中心を通る座標へ調整する (そうしないと白と黒がにじむ)。OpenGL ES では
  3D テクスチャが無いため、色管理を当てずに出す。
- **輝度の重み**: 定数表ではなく、色空間から導く (sRGB なら 0.2126 / 0.7152 / 0.0722)。画面の Gray 表示、画素値表示、ルーペ、
  差分、変化グラフが、すべて同じ重みを使う (以前は 3 通りが食い違っていた)。
- **解析値の空間**: ファイルのまま (`source`、既定) か線形光 (`linear`) から選ぶ。既定を `source` にしたのは、既存の数値
  (過去の計測) が変わらないため。`display` は、実際に要求が出てから足す (どの画面のプロファイルで測ったかが数値に付いて回る)。
  輝度は、線形へ戻してから重みを掛ける。表示には効かない。
- **白黒反転**: 表示される値に対して、露出とガンマの後で `255 - 値` とする。データの最大値を基準にした反転は採らない
  (画像ごとに基準が変わり、比較にならない)。1.0 を超える領域を潰さずに反転したいときは、露出を下げてから反転する。
- **浮動小数画像のトーンマッピング**: 露出 (段数、全セル共通) で行う。**最大値による自動正規化は採らない** (画像ごとに
  基準が変わり、比較にならない)。露出は表示だけに掛け、画素値、ヒストグラム、差分は解析用バッファの値をそのまま使う。

## 解析用バッファと表示

- **決定**: 解析用バッファは、元ファイルの画素の精度 (`uint8`、`uint16`、`half`、`float`) のまま持つ。`float32` へは
  演算のときに変換する。表示用の 8bit `QImage` とは別に持つ。
- **理由**: 目的は量子化による情報の欠落を防ぐこと。8bit を `float32` へ広げても情報は増えず、メモリが 4 倍になる。
  複数枚を並べて比較する用途で、常駐量が過大になる。
- **画素値、ルーペ、ヒストグラム、差分、変化グラフは、解析用バッファの値を使う**。表示用の画像 (露出などを掛け、
  0 から 1 に収めた後のもの) からは求めない。
- **画素値の単位**: `0-255` と `0.0-1.0` を切り替えられる (既定は `0-255`)。精度ごとに単位を変える案 (16bit なら 0-65535)
  は採らない (ビット深度の違う画像を並べたとき、単位が混在して比較の目的に反する)。小数の桁は、16bit の 1 階調を分解できる
  最小の桁。8bit 由来の 16bit 値 (257 の倍数) は、`0-255` で整数に乗る。
- **解析用バッファを持たない 8bit 画像がある**: Qt で読む PNG / JPEG の 8bit は、表示用の画像がそのまま元データで、
  別に持たない。

## キャッシュとメモリ

- **復号キャッシュ**: エントリ数ではなく、**バイト数のソフト上限** (既定 1 GiB)。破棄の順は 3 段 (現在のページ以外で、解析用
  バッファを持ち、保持範囲の外にあるもの > 現在のページ以外 > 現在のページ)。保持範囲 (現在のページと前後 1 ページ) は、
  「予算を超えたときに最初に捨てる候補」を表すだけで、**範囲の外だからといって無条件に捨てない** (捨てるかどうかは予算で
  決める。範囲で二重に絞ると、予算がほぼ意味を失い、ページ送りのたびに読み直していた)。
- **先読み**: 距離は、**予算に何ページ入るか**から決める (入りきらない分を読んでも、届いたそばから捨てられて無駄になる)。
  1 ページも入らない場合でも、隣までは読む (ここを 0 にすると、ページ送りが毎回、復号待ちになる)。セルごとに別の画像を
  出すときは、1 ページが複数のエントリになる。読む順は、近い側から交互。方針は `PrefetchPlanner` にあり、直接テストしてある。
- **GPU テクスチャ**: 上限は**全セルの合計**に掛け (既定 2 GiB、設定で変えられる)、溢れたら全セルを通して、最も使われていない
  ものから捨てる。セル数で割る案は採らない (テクスチャの少ないセルの枠が余り、多いセルが使えない)。`TextureBudgetLedger` は
  捨てるものを決めるだけで GL に触れず、持ち主が次に描くときに消す (他のセルの描画中に、コンテキストを切り替えて消せないため)。
  描いているものは、予算を超えていても捨てない。作業セットが予算を超える並び (周回) は、LRU にとって最悪で遅くなる。
- **解析用バッファの寿命**は、表示用の画像より短い (4K の 16bit は 66 MiB で、セル数 x ページ数で効く)。範囲外のものは
  丸ごと捨てる (表示用の画像だけ残しても、画素値の表示とテクスチャに解析用バッファが要るため使えない)。
- **キャッシュの効きは、カウンタで見る**。ヒットとミスを、引きに行ってから数える (先に存在を確かめる形だと、ミスが数に入らない)。

## GPU 描画

- **範囲**: GPU で処理するのは、デコードではなく、表示変換と描画。PNG のデコードは逐次処理で GPU に載らず、結果を読み戻す
  必要が必ず出る (解析は CPU で行うため)。解析経路は CPU のまま。
- **テクスチャの形式**: 解析用バッファを持つ画像は `RGBA16F` (露出で 1.0 を超える領域を復元できる)。`RGBA32F` は
  半精度で足りる上に 4K で倍の VRAM になるため選ばない。**16bit 整数だけは、正規化整数 (`RGBA16`) で、変換なしに載せる**
  (内部形式を型に合わせないと、ドライバの変換で 79-86 ms かかるが、合わせれば 7-9 ms で、精度も落ちない)。
  8bit は、並びが合う形式 (BGRA / RGBA) を詰め替えずに渡す。**詰め替えず、変換させない形を選ぶ**のが一貫して効く。
  浮動小数と 1-2 チャネルは、`half` への詰め直し (並列) を通る。
- **描画の作り**: 回転と反転はテクスチャ座標側で、フラグメントシェーダは色の変換だけ。透過の下地は、シェーダの中で合成する
  (`glScissor` と `glClear` で下地を塗ると、端数の丸めで画像の外へ 1 画素はみ出し、パンのたびに線がちらつく)。縮小は
  ミップマップに任せる。パン時の差分スクロールは使わず、毎回全面を描き直す (`QOpenGLWidget` は部分更新を持たない)。
- **描き直しの頻度**: マウスは毎秒 700 回ほど動きを送ってくるが、画面が出せるのは更新レートの分だけ。**画面の更新
  (vblank) に合わせて描く** (`DisplayLink`、DXGI の `WaitForVBlank` を専用のスレッドで待つ)。
  - 更新レートちょうどを狙う自走タイマーは、揺れで必ず 1 枚飛ぶため、破綻する。
  - **`DwmFlush()` は vblank の時計にならない** (合成の完了を待つだけで、間隔が更新レートと一致しない)。
  - `QOpenGLWindow` にしても画面の更新には揃わない (`swapInterval` が効かない)。`QOpenGLWidget` のままでよい。
  - 合図が来ない環境 (遠隔接続、仮想ディスプレイ) では、更新間隔で時間刻みにする。合図が出ている間は、更新間隔の 1.5 倍を
    過ぎても来なければ自分で描く。
  - 揃えると進み方は均一になるが、応答が 1 回分遅れる。`HEIRAN_PAN_SYNC=0` で切れる。十字のカーソルは、ハードウェア
    カーソルのマウスポインタより必ず遅れる。
- **計測の注意**: UI スレッドの時間だけを見ると、GPU と vsync の待ちが入らず、速く見える。間隔の計測は、入力が途切れた区間を
  除く (手が止まった時間を、詰まりと読み違える)。平均だけでなく、最大と最小も出す。合成入力 (PowerShell からのマウス移動)
  では毎秒 20 回ほどしか送れず、実機の頻度で起きる問題は再現できない。

## 解析機能

- **窓の扱い**: ヒストグラム、差分、変化グラフは独立した窓。閉じても破棄せず隠し、**隠れている間は計算しない**
  (届いた分は保持し、次に開いたとき 1 度だけ計算する)。この規則は `AnalysisWindowBase` に 1 つだけ置く
  (窓ごとに書くと食い違う)。解析の対象は、全セルの `AnalysisImage` の並び。選択範囲があれば、その範囲だけを集計する。
- **ヒストグラム**: 縦軸は**画素数で割った割合** (大きさの違うセルを比べられる)。軸の上限は最大の度数ではなく**倍率**で決める
  (山が動くたびに全体の高さが変わると、コマ送りで形の変化と区別がつかない)。対数軸は倍率とは別の操作。横軸は全セル共通で
  `0.0` から実データの最大値まで (最大値の下限は 1.0。整数画像は従来どおり)。**平均と標準偏差、最小、最大は、ビンではなく画素の値から
  求める** (ビンは 256 段へ丸めた後で、誤差が乗る)。最頻値だけはビンから取る。
- **変化グラフ**: 縦または横に平均してプロットする。既定は、セル別の図を並べる (セルを重ねると N x 3 本で読めない)。セルを重ねる
  表示は、チャネルを輝度に固定する。縦軸の上限は、整数画像では 1.0 で固定 (軸が動くと形の変化と区別がつかない)。横軸は
  画像座標。和は `double` で持つ。
- **結果のキャッシュ** (`AnalysisResultCache`): 鍵は**画素データの同一性** (ファイルのパスではない。同じファイルを別のセルで
  開いた場合や、再読込で中身が変わった場合に取り違える)。`QImage::cacheKey()`、解析用バッファの番地、バイト数の 3 つが
  一致することを求める (解放された領域の再利用による取り違えを避ける)。鍵に入れるのは集計に影響するものだけ (表示側の露出や
  チャネルは入れない。回転と反転は走査の並びが変わるため入れる)。上限は件数 (64) だけで足りる。
- **差分**:
  - 差は、比べる側 - 基準 の**輝度** (色空間から導いた重み)。モードは絶対値 / 符号付き / 二値、見せ方はグレー / 符号の色 /
    重ね合わせ。数値指標は、最大、平均、符号付きの平均、RMSE、PSNR、閾値を超えた画素の数。
  - **差分は、セルとして並べて見られる**。別ウィンドウだけでは、ほかのセルと同期して見比べられなかった。
    空きセルへ「基準」と「比べる側」の差分を出す方式と、画像のあるセルを、基準のセルとの差分に置き換える方式の両方を持つ。
    **差分のセルは、通常のセルとして動く** (差分の絵を普通の画像として渡すため、ズームとパンの同期、画素値の表示、解析ウィンドウが
    そのまま使える)。各セルが見せる元の画像は別に持ち、入力か設定が変わったときだけ作り直す。回転と反転は掛けない (各セルが見せる
    元の画像の画素どうしで作る)。差分のセルを元にはしない。
  - 求め方と指標は、画像の面の**下端に重ねる帯**に出し、**マウスが乗っている間だけ**見せる (レイアウトに入れると画像の面が縮み、
    他のセルと表示位置がずれる。上端にはセルのラベルが出る。一覧を開くとマウスがセルの外へ出るため、入力の途中は隠さない)。
    **そのほかの設定は、歯車のボタンで開くポップアップ**に置く。すべてを帯に並べると、狭いセルで選択肢の名前が欠けた
    (展開式にすると、帯が高くなり、小さなセルでは画像より大きくなる)。ポップアップなら、狭くても欠けず、項目名つきで、選択肢を略さずに読める。
    ポップアップが開いている間は、入力の途中として扱うため、帯は隠れない。指標は、幅を超えたら省略記号で切る。
  - **大きさの違う画像**は、既定では**左上をそろえて、重なる部分だけを比べる**。指定すれば、基準 / 比べる側 / 大きいほうの大きさへ
    合わせる (縮小は元の画素の重なりでの面積平均、拡大は線形補間。輝度の平面で行うので、元の精度のまま比べる)。
  - Diff ウィンドウは、選択範囲の差分用に残している。描画は共通 (`renderDiff`)。
- **速さの方針**: 全画素を走査する解析は、画素ごとに型や座標の写しを判定せず、**走査の外へ出して、平面を作ってから畳む**。行を帯に
  分けて並列にする。**手を入れる前に、内訳を測る** (並列化だけでは伸びず、`std::lround` の関数呼び出しが集計の大半だった、
  という具合に、重い所は思い込みと違った)。SIMD の手書きと GPU は採らない (自動ベクトル化で足り、GPU は結果の読み戻しで差が
  出ない)。3 つの平面は同時に持たない (4K で 1 つ 33-64 MiB)。2048 x 2048 の差分が 2261 ms から 46 ms、4K の 3 次元ヒストグラムが
  約 600 ms から約 105 ms、TIFF の展開が 228-407 ms から 41-74 ms になった。
- **色差 (ΔE2000)**: 輝度の差とは別の指標で、画素ごとの費用が桁違いに大きいため、**計測してから入れる**ことにした
  (`heiran_diff_benchmark`、合成した 4K の 8bit 画像、中央値)。
  - 基準: 輝度の差 (`renderDiff`) が約 80 ms。色差には、これに加えて、RGB の 6 平面を作る費用 (約 105 ms) が要る。
  - 素朴な実装 (論文の式どおり、`std::cbrt`、`std::pow`、角度の三角関数) は、全画素が違うとき約 475 ms (並列)。
  - 色相を角度ではなく**単位ベクトル**で持ち (平均の色相は 2 つの和の向き、倍角と 3 倍角は加法定理)、累乗を乗算にし、立方根を
    Halley 法の 2 回で詰めると、約 175 ms (全画素が違う) / 約 20 ms (1 割が違う。同じ画素は計算を飛ばす)。
    基準の実装 (`deltaE2000`、論文の検証用データの 7 組と一致) との差は、20 万組で 1e-6 未満。
  - 色相がちょうど反対の組は、基準の実装も丸めの誤差で向きが決まる (不連続)。高速な版は、角度の差の符号に合わせる。
  - **平面の作成**: 3 チャネルを別々に 6 回作ると約 107 ms だったが、画像を 1 回だけ走査して 3 つの平面を書く
    (`buildRgbPlanes`。0 で埋め直さない) と約 25 ms。回転も反転も無く、領域が画像の全体なら、並べ替えの複写も省く
    (ヒストグラムなどの 1 チャネルの経路も、約 107 ms から約 57 ms)。線形光への写しも、行を帯に分けて並列にした。
  - **画面への出し方**: 差分の**モード**の 1 つ (`delta-e`) として足した。輝度の差の経路は変えず、既定にもしない (選んだときだけ計算し、
    入力か設定が変わったときだけ作り直す)。Lab は線形光で測る必要があるため、値の空間の設定は線形へ固定する。
    符号が無いので、符号付きの見せ方は持たない。閾値の尺度が違うため、既定のままなら、モードの切り替えで 8 と 2.3 を入れ替える。
  - **全体の時間** (`renderDiff` を通した、4K の合成画像): 全画素が違うとき約 340-500 ms (平面の作成、ΔE の計算、画像への描き分けを含む。輝度の差は、約 80-110 ms)、
    1 割が違うとき約 260 ms。計算と平面の作成だけでは、約 200 ms。
  - **見直す条件**: 4K の全画素が違う場合で、約 200 ms (平面の作成を含む。最初の実装は約 590 ms)。画面の応答に響くなら、別のスレッドで計算して、前の結果を
    出したままにする。それでも重ければ、縮小した画像での近似か、選択範囲だけの計算を検討する。
- **SSIM**: ΔE2000 と同じく、差分のモード (`ssim`) として、**計測してから**入れた。窓は、標準の 11 x 11 のガウス窓 (σ = 1.5)。
  - **作り方**: 窓の平均 (x、y、x²、y²、xy の 5 つの量) を、水平、垂直の 2 度のぼかし (分離できる窓) で求める。行を 64 行の塊に分けて処理し (作業用の領域は、
    幅に比例した大きさ)、全体は、行を帯に分けて並列にする。参照 (scikit-image) と、画素の値で 1e-4 以内に一致する (試験は、参照の値を埋め込んでいる)。
  - **計測** (4K、合成画像): SSIM の計算が約 36 ms (並列、輝度の平面ができているとき)、輝度の平面 2 枚が約 37 ms。`renderDiff` を通した全体は、約 150 ms
    (輝度の差の約 1.4 倍)。素朴な窓 (11 x 11 を画素ごとに数える) を避け、**分離したぼかし**にしたことと、内側の繰り返しが、自動でベクトル化されることが効いた。
  - **端の扱い**: 端の画素を延ばして補う。参照 (反射) と、端から 5 画素の内側は一致するため、**指標は、内側だけ**で数える。
  - **見せる値**: 1 - SSIM。ほかのモードと同じ「差の大きさ」の扱い (自動の範囲合わせ、倍率、重ね合わせ) へ、そのまま乗る。閾値は、SSIM の値 (既定 0.9)。
  - **見直す条件**: 色ごとの SSIM (RGB、または、MS-SSIM) が要るとき。
- **並列にしないもの**: PNG の展開 (逐次処理)。
- **ワイプは、差分のモードの 1 つとして足した** (`DiffMode::Wipe`): 別の種類のセルを足すと、基準と比べる側の選び方、大きさの合わせ方、帯、`.hrn`、
  作り直しの規則を、もう 1 組作ることになる。差分の仕組みへ乗せれば、これらを共有でき、ほかのセルと同期して動く。境目の線は、画像の座標で持つ
  (拡大と移動に追従する。画面に固定する案は、描画 (GPU) へ 2 枚目の画像を足す大きな変更になるため、必要になるまで採らない)。線のドラッグは、
  セルの上に重ねた部品が受け、新しい位置を、通常の差分の設定の変更と同じ経路で返す (作り直しは、位置が変わるたびに、行ごとの複写)。
  8bit に直した絵からつなぎ合わせるため、16bit や浮動小数の元の値は、見えない (値の比較は、差分と画素値の読み取りで行う)。
  **見直す条件**: 画面に固定した境目が欲しいとき、または、元の精度のままつなぎ合わせたいとき。
- **波形モニタとベクトルスコープ**: 独立した解析ウィンドウ (`WaveformWindow`、`VectorscopeWindow`) として足した。差分のモードにしなかったのは、
  結果が、2 枚の関係ではなく、1 つのセルの信号の分布で、セルごとに出すものだから (ヒストグラムや変化グラフと同じ種類)。
  - **集計と描き起こしを分けた**: 升目への集計 (`domain/Scopes`。純粋な関数で、帯ごとに数えて足し合わせる) と、升目から絵への起こし (`ScopeBuilder`) を分ける。
    絵は、表示の切り替え (輝度、RGB、Parade、明るさの倍率) のたびに、取っておいた升目から起こす (数え直さない)。
  - **濃さの決め方**: 波形は、列ごとの密度 (列の画素が一様なら 1)。画像の大きさに依らず、見え方が揃う (全体の最大で割ると、白飛びした 1 列が、ほかを暗くしてしまう)。
    ベクトルスコープは、対数 (色の少ない画像では、点が数個になる。まばらな升目も見えるようにし、光の点は、上下左右へ弱くにじませる)。
  - **面の色**: 配色 (Light / Dark) に関わらず、暗い中立な下地。明るい下地では、光の点が見えにくい (画像を見比べる面と同じ考え方)。
  - **計測** (4K、合成画像): 波形の集計が約 33 ms (4 つの平面を同時)、ベクトルスコープが約 19 ms、波形の絵 (Parade) の起こしが約 24 ms。
  - **見直す条件**: 横の向き (行ごとの波形) や、縦の分解能の指定、HDR の値の幅の指定が要るとき。
- **差分の性能** (4K、合成画像、全画素が違う場合): 輝度の差の全体が約 110 ms から約 60 ms、SSIM が約 148 ms から約 96 ms、ΔE2000 が約 503 ms から約 280 ms
  (1 割が違う場合は、約 260 ms から約 90 ms)。**倍率、見せ方、閾値の変更は、約 7-11 ms** (ΔE は約 380 ms から約 7 ms)。
  - **差の場を取っておく**: 重いのは、輝度の差、ΔE、1 - SSIM の**場**を作るところで、倍率、見せ方 (グレー、符号の色、重ね合わせ)、閾値、範囲合わせは、
    場から絵と指標を作り直すだけで済む。場 (`DiffField`) を、セルごとに取っておき、基準と比べる側 (の画像の世代) と、計算の種類 (輝度の差 / ΔE / SSIM)、
    大きさの合わせ方が同じなら、使い回す。absolute、signed、binary は、同じ場を共有する。取っておく量は、4K で 1 セルあたり約 33 MB。
    **場は、設定が変わるたびに捨てられていた** (`setCellDiff` が、状態を空にしていた) ため、使い回しが、最初は効かなかった (試験で見つけた)。基準や比べる側が
    同じなら、状態を残す。
  - **画素の色づけの分岐を、ループの外へ出した**: 計算の種類と見せ方を、型 (テンプレート) で選び、画素ごとの `switch`、`double` の丸め、色の組み立てをなくした。
    絵は、RGBA8888 で、全画素を書く (塗りつぶしと、後の形式の変換が、要らなくなる)。
  - **指標も、並列に**: 帯ごとの部分の合計を足し合わせる (`DiffMetricsPartial` など)。以前は、1 スレッドの 1 回の走査だった。差の列の作成も並列にした。
  - **線形光への復号の表**: ΔE の入力は、線形光へ直した値で、4K の 6 つの平面の累乗が、約 100 ms かかっていた。4096 区間の表と線形補間にした (誤差は float の精度より小さい)。
    ヒストグラムなど、解析の値の空間を線形にしたときの平面の作成も、同じ表を使う (輝度の平面の作成は、並列にもした)。
  - **ΔE の計算そのもの** (約 175 ms) は、残る。三角関数と平方根の数を減らしてあり、これ以上は、近似式への置き換えか SIMD が要る。
    入力が変わる操作 (ページ送り) では、これだけの時間、UI が止まる。**見直す条件**: 実機で、ΔE のセルのページ送りが重いとき (別のスレッドで計算して、前の絵を出したままにする)。

## 操作と画面

- **見た目**: 画像を邪魔しない、控えめなダーク。**画像を出す面は、配色に従わず、中立な暗い下地に固定する** (周りの明るさで
  画像の印象が変わると、比べる道具として使えない)。ウィジェットの配色は Qt に委ね (`QStyleHints::setColorScheme`)、パレットを
  自前で組まない (標準のダイアログだけ浮く)。解析グラフは配色に追従させ、文字と下地の明暗差をテストで固定する。
- **既定**: Pixel Info ドックは閉じて始める。引数なしの起動は、空の 1 セル (パスがカレントディレクトリ基準で、2x2 の例を
  返すと、エクスプローラからの起動で 4 セルとも読込失敗になる)。
- **エラーの見せ方**: 要約 (失敗内容、対象、次の操作)、詳細の一覧、固定の操作の 3 部構成。空欄のセルは、中立な「画像なし」。
  読込に失敗したセルは、ファイル名、簡潔な理由、再読込を出す (空欄と見た目を分ける)。
- **キーボード**: ページ送りの矢印キーが、ツールバーの入力欄にフォーカスを取られないよう、入力欄は `Qt::TabFocus` を持たない。
  事象 (矢印が効かない) は合成イベントで再現できないため、**原因 (入力欄がフォーカスを取れる状態) をテストで固定する**。
- **ファイルの操作**: 名前の変更 (上書きしない)、ごみ箱 (確認を出し、既定 Yes)、パスのコピー、印刷、フォルダで表示。操作の中身は
  ダイアログと分け、ごみ箱の移動は差し替えられる (テストが実際のごみ箱を汚さない)。
- **全画面**: 画像だけを見せる状態。メニューもツールバーも隠れるため、画像の上に短いメッセージ (ページ送り、露出、操作の結果、
  抜け方) を出す。マウスは動かさなければ隠す。露出は `[` `]` で操作する。
- **カーソルと選択範囲**: 線の下に暗い縁を敷く (色だけでは、似た色の画像で溶け込む)。もう 1 つの方式として、カーソルの下の
  画素の色から、**CIELAB の色差が最も離れる色**を、白、黒、彩度の高い 6 色から選ぶ方式もある (View > Cursor)。単純な反転は
  中間のグレーで元の色と同じになる。
- **サムネイル一覧**: 形式ごとに読み方を変える。専用のスレッドプールで読む (復号の内側の `blockingMap` が共有のプールを待つと止まる)。
  ディスクへ取っておく。Windows のシェルへサムネイルを提供することは、していない (Windows が扱える形式は WIC が速く、
  扱えない形式 (exr / hdr / tga / dpx) は、COM のサロゲートへ読み込まれる独立した DLL が要る。やるなら、WIC のデコーダを書くほうが筋が良い)。
- **画像セットとセルの編集は、表で行う** (`ImageSetManagerDialog`): 画像セットを 1 行 1 件の表 (名前、ラベル、ラベルの表示、パス、見つかった数、
  ページのずれ、既定の倍率、EXIF、使っているセル) で並べ、セルを別のタブの表 (画像セット、倍率、ガンマ、回転、反転、白黒反転、チャネル、同期) にした。
  フォームと一覧の組み合わせでは、多数の画像セットを見比べられず、同じ値を続けて入れるのが手間だった (Path の欄も狭かった)。
  - 値は、表の編集のたびに結果へ戻す (OK までは、呼び出し側へ反映しない)。長さのある項目 (見つかったファイルの一覧) は、選んだ行の下に出す。
  - **倍率の持ち方**: 画像セットの倍率は、セルへ割り当てるときの**既定値**で、割り当てたあとは、セルの倍率が独立する。画像セットの既定を変えたら、
    それを使うセルの倍率も同じ値にする。セルへ別の画像セットを割り当てたら、そのセルの倍率を、新しい既定にする。反映は、ダイアログの表の編集が行い、
    `applyImageSetEdit` は、受け取ったセルを、そのまま採る (以前は、反映のたびに、全セルの倍率を、画像セットの値で上書きしていたため、セルごとの
    倍率を、あとから変えられなかった)。
  - 画像セットの並べ替えと複製、削除では、セルが同じ画像セットを指し続けるよう、番号を付け直す (並べ替えるだけで、見えている画像が変わらない)。
  - 差分のセルは、帯から設定するため、表では触らせない (行を灰色にして、値は、そのまま結果へ残す)。
  - **見直す条件**: セルの設定を、表以外の画面 (右クリック) と二重に持つことの混乱が出たとき。
- **単独表示 (A/B の切り替え)**: 1 つのセルを、格子の全体へ広げて見せる。格子を 1x1 へ切り替える方式にしなかったのは、セッション (格子の形、
  割り当て、`.hrn`) を変えてしまい、元へ戻すときにセルごとの設定を保ちにくいため。**セッションは変えず、表示だけを絞る** (未保存の印も付けない、
  `.hrn` へも保存しない)。ほかのセルは隠すだけで、解析と画素値の対象には残る。拡大縮小と移動は、全セル共通の基準で動くので、切り替えても同じ場所を
  同じ倍率で見続けられる (A/B の肝)。
  - キー: <kbd>Tab</kbd> / <kbd>Shift</kbd>+<kbd>Tab</kbd> が、入ることと、次 / 前のセルへの切り替えを兼ねる (画像のないセルは飛ばす。差分のセルは対象)。
    <kbd>Alt</kbd>+<kbd>1</kbd>-<kbd>9</kbd> が直接指定、<kbd>Esc</kbd> と <kbd>Alt</kbd>+<kbd>0</kbd> が戻る。数字キー単独は、ズーム (<kbd>1</kbd>、<kbd>0</kbd>)
    が使うため割り当てない。<kbd>Esc</kbd> は、選択範囲があればその解除を優先し、無ければ単独表示を抜ける。
  - **フィットの扱い**: 入るとき、戻るときに、見ていた状態がフィットなら、広がった (縮んだ) 面へフィットし直す (セルの大きさが定まったあと、
    キューへ積んで行う)。拡大や移動をしていたなら、そのまま保つ。フィットかどうかは、いまの面の大きさから求めたフィットの結果と、基準の倍率と位置を、
    比べて決める。フィットの大きさは、単独表示では、そのセルの面から取る (先頭のセルは隠れていて、大きさが無い)。
  - セルを作り直す操作 (ファイルを開く、格子の変更、画像セットの編集) では、単独表示を解く。作り直さない更新 (差分の設定、ページ送り) では保つ。
  - **見直す条件**: 押している間だけ別のセルを見せる「ピーク」や、一定間隔で自動で切り替える「点滅」が要るとき。ワイプは別の機能として検討する。
- **案内 (起動直後の画面)**: 画像を 1 枚も開いていないとき (どのセルにも画像も差分も無いとき) だけ、画像の面へ、案内 (`WelcomeWidget`) を重ねる。
  背景は画像表示面と同じ中立色で塗り、背後の空セルの文が重ならないようにする。
  内容はスクロール領域に置き、小さい窓でも文字やボタンを重ねない。長い最近の画像名は中央を省略し、全体はツールチップで読める。
  ドロップ、開くボタン、キーの一覧、最近開いた画像 (5 件)。以前は、空のセルの小さな文字と、ステータスバーの 1 行だけで、初めて使う人が、
  何をすればよいか分からなかった。案内自身がスクロールとボタン操作を受け、ドロップはセルへのドロップと同じ経路で開く。
  最近の画像は、同じ連番の名前を見分けるため、フォルダ名を添える。
- **画素の値は、ステータスバーにも出す**: Pixel Info のドックは、既定で閉じていて、Heiran の中心機能 (同じ位置の値を、全画像で並べて読む) が、
  開くまで見えなかった。ドックを開き直さなくても読めるよう、位置と各セルの値を、ステータスバーに短い 1 行で出す (`x=87 y=33  [1] 242 244 247  [2] ...`)。
  値は、ドックと同じ行 (`buildHoverDetails`) から作る (単位の設定に従う。桁揃えの 0 は落とす)。セルが多いときは、先頭の 4 つと残りの数。
  ドックを既定で開く案は、画面を狭くするため採らない。
- **操作の対象のセルを、枠で示す**: 複数のセルが見えているとき、操作の対象 (マウスを最後に置いたセル。チャネルの切り替えと画像のコピーが効く) を、
  縁の細い青い枠で示す (単独表示と、セルが 1 つのときは出さない)。枠は、画像の面 (GPU) の上へ重ねる軽い部品にした (描画の側で描くと、
  毎回の再描画が要り、画面の書き出しにも写らなかった)。マウスは、下へ通す。
- **全画面で、上端へ寄せたら、メニューとツールバーを出す**: 全画面で隠したため、露出などの操作に戻れなかった。マウスが画面の最上段へ寄ったら出し、
  画像の面へ降りたら (350 ms 待って) 引っ込める。メニューを開いている間は引っ込めない。出すと、画像の面が、その分だけ下へずれる (拡大率は変わらない。
  画像へ重ねる方式は、メニューバーとツールバーが、QMainWindow の部品のため、採らなかった)。
- **元に戻す (Undo / Redo)**: 画像の割り当て、格子、画像セット、並べ替え、ラベルといった、**セッションの構造の変更**を、30 件まで戻せる
  (Images メニュー、Ctrl+Z / Ctrl+Shift+Z、項目に操作の名前を出す)。誤操作 (Clear All Cells など) の怖さを減らすため。仕組みは、変更の前の状態
  (セッション、セルの配置の控え、ページ、未保存の印) を丸ごと控えて、戻すときに、いまの状態を、やり直しの側へ積む (差分の保存ではなく、全体の複製。
  画像セットのファイル一覧が大きくても、30 件なら足りる)。変更が起きなかった場合 (早期の return) は積まない。新しい変更で、やり直しを捨てる。
  別のセッションや画像を開いたら、履歴を捨てる。格子を広げて差分のセルを足す操作は、1 件にまとめる。戻したあとの未保存の印は、変更の前の値に戻る。
  - **対象にしないもの**: 拡大、パン、セルごとの倍率やガンマ、回転、反転、チャネル (操作が連続して多く、1 つずつ戻す意味が薄い)。差分の設定の変更。
  - **見直す条件**: セルごとの設定も戻したい要望が出たとき (連続した操作をまとめる仕組みが要る)。

### 表示を絞ったときの操作

- **決定**: `ViewerChromeController` が、全セルのヘッダー表示とナビゲーションを隠したときの小型ページ操作を管理する。
  ヘッダーは既定で表示し、切り替えを利用者設定に保存する。小型ページ操作はステータスバーの右側へ置き、通常のナビゲーションと同じアクションで前後へ移動する。
- **理由**: 画像に使う面積を増やしながら、マウスでページを選ぶ導線を残す。メニューバーの横へ置くと、小さい窓でメニューの幅を圧迫するため、下部を使う。
- **見直す条件**: ステータスバーも隠した状態でマウスのページ操作が必要になったとき。

### 元ファイルを他アプリへドラッグする操作

- **決定**: Ctrl + 左ドラッグを使い、`FileDragController` が操作の判定とコピー専用のファイル URL の受け渡しを持つ。
  元ファイルをそのまま渡し、表示用画像の再書き出しは行わない。
- **理由**: 通常のパンと Shift による範囲選択を維持し、Discord などファイルを受け付けるアプリへ、形式や精度を変えずに渡せる。
  コピーだけを許可することで、比較中の元ファイルの移動を防ぐ。
- **見直す条件**: 表示結果や選択範囲を書き出して渡す操作、または修飾キーなしで使える専用のドラッグ領域が必要になったとき。

### 設定ダイアログの構成

- **決定**: 左のカテゴリ一覧と右のページを使い、全般、表示・再生、色管理、キャッシュに分ける。
  ページは作成後に保持し、右側だけをスクロール可能にする。OK・キャンセルはページの外に置き、全ページを一括で確定・破棄する。
  ページ下部に高さを固定した説明領域を置き、`SettingsHelpController` が項目・ラベルへのマウス操作と入力欄内部へのフォーカスを拾って案内を切り替える。
  説明は次の項目へ移るまで保持し、長文は領域内でスクロールする。適用時期や選択できない理由は項目付近にも残す。
- **理由**: 項目が増えてもダイアログ全体を縦に伸ばさず、関連する設定を探しやすくする。ページ切り替えによる変更の消失や意図しない適用を避ける。
  ツールチップの表示待ちや消失に左右されず、マウスとキーボードのどちらでも説明を読めるようにする。説明の切り替えでレイアウトを動かさない。
- **見直す条件**: カテゴリ内の項目がさらに増えて検索やカテゴリの分割が必要になったとき。

## ビルドと配布

- **ビルド**: Windows、Ninja、Clang (`clang-cl`)。PowerShell のスクリプト (`scripts/*.ps1`) が入口で、`Launch-VsDevShell.ps1` 系で開発シェルへ
  入る (繰り返し呼ぶと `INCLUDE` / `LIB` が累積するため、実行の前後で環境を保存、復元する)。**`scripts/*.ps1` は ASCII だけ**
  (Windows PowerShell 5.1 は BOM 無しを ANSI として読む)。`CMAKE_BUILD_TYPE` を正とする (Ninja は単一構成で、`--config` は無視される)。
  性能の判断は Release で行う。
- **コンパイラ**:
  - **決定**: CMake の C++ コンパイラに `clang-cl` を明示する。Visual Studio 同梱の x64 版を優先し、なければ PATH から探す。
    MSVC 互換の ABI を使い、Qt の MSVC 版と vcpkg の `x64-windows` を利用する。SDK、標準ライブラリ、リンカは Visual Studio の開発環境を使う。
    異なるコンパイラの CMake キャッシュは通常の configure で拒否し、`-Clean` による再構成を求める。
    ASan は Clang 付属のランタイムと thunk を明示してリンクし、実行中の PATH にランタイムの場所を追加する。
  - **理由**: Clang を使う方針を明示し、環境変数によって意図せずコンパイラが変わることを防ぐ。既存の Qt と依存ライブラリに組み合わせられる clang-cl を使う。
    CMake がリンカを直接呼ぶため、ASan のコンパイル指定だけでは Clang のランタイムがリンクされない。
  - **見直す条件**: Qt と依存ライブラリを含めて ABI や標準ライブラリを変更するとき。
- **ビルド設定の既定値**:
  - **決定**: `scripts/common.ps1` に Release などの共通の既定値を集める。Qt の場所は環境変数 `Qt6_ROOT` の設定を推奨し、
    CMake の探索と各スクリプトの DLL 探索に同じ場所を使う。`local.settings.ps1` は任意とし、必要な環境差分だけを書く。
    ローカル設定による上書きは維持し、Debug は `configure.ps1 -BuildDir build-debug -BuildConfig Debug` で別に作れる。
  - **理由**: 雛形へ既定値を複写すると、リポジトリの方針を変えても既存のローカル設定に反映されない。環境差分と共通方針を分けて管理する。
    Qt の場所を環境側に設定すれば、リポジトリごとに設定ファイルを作らずに済み、直接 CMake を使う場合も同じ環境変数を利用できる。
  - **見直す条件**: IDE や CI と設定を共有する必要が生じたときは CMake Presets への集約を検討する。
- **依存の導入**:
  - **決定**: vcpkg の manifest モードをビルドスクリプトで必須にする。配置先はローカル設定、`VCPKG_ROOT`、`.tools/vcpkg` の順で決める。
    `vcpkg.json` を正とし、セットアップと CMake はルートの `vcpkg_installed/` を共有する。configure 時に不足する依存を導入する。
  - **理由**: vcpkg の指定漏れで対応形式が減ることを防ぐ。導入先を揃え、セットアップで入れた依存を CMake でも使う。
  - **見直す条件**: triplet やマニフェストの機能をビルドディレクトリごとに変える必要が生じたときは、依存の導入先も分離する。
- **配布**: CPack で NSIS のインストーラと ZIP。`heiran.exe` は `bin/` に置き、Qt のデプロイスクリプトが `qt.conf` を置く。
  DLL は `RUNTIME_DEPENDENCY_SET` で集める (`$<TARGET_RUNTIME_DLLS>` は、リンク先の DLL しか返さない)。動作確認は、ZIP を
  ビルドディレクトリの外へ展開して行う (中だと、そこにある DLL を拾い、足りない DLL に気づけない)。
- **ファイルの関連付け**: NSIS の選択用セクションとカテゴリを使い、`.hrn`、一般画像、高精度画像の順に並べる。
  すべて既定で有効とし、画像のカテゴリは一括でも拡張子単位でも選択できる。画像形式は拡張子の既定を奪わず、
  `OpenWithProgids` と `RegisteredApplications` へ登録するだけ (Windows 10 以降は UserChoice のハッシュで既定を管理していて、
  インストーラが黙って差し替えられない)。アンインストールでは拡張子のキーを消さず、`OpenWithProgids` の値だけを消す
  (キーは他のアプリの持ち物)。
- **落ちたときの記録**: `SetUnhandledExceptionFilter` でミニダンプ (全メモリは落とさない) を書く。落ちる前に経路を作っておく。
  子プロセスで実際に落として、書けることをテストで固定する。
- **アイコン**: 2x2 のパネルに同じ位置のカーソル。32px 以下は十字を点へ落とす。`.ico` は小サイズを DIB、256px を PNG にする
  (NSIS は PNG だけの `.ico` を受け付けない)。標準ライブラリだけで生成する。
- **OpenGL を動作の要件にし、ソフトウェアの OpenGL は配布しない**: `opengl32sw.dll` (約 21 MB) は、GPU の無い環境 (リモートデスクトップ、仮想マシン) の保険だが、
  今は、そのような環境が、ほぼ無い。入れると、インストーラが大きくなり、LZMA の時間 (1 MB あたり約 0.45 秒) も、約 9 秒かかる。外して、要件を
  **OpenGL 3.0 以上に対応した GPU とドライバ**にした (シェーダは、GLSL 1.20 の書き方だが、`RGBA16F` のテクスチャが、3.0 を要る)。
  OpenGL が使えない環境で、何も出ない窓が開くのを避けるため、起動の前に、コンテキストを作れるかと、バージョンを確かめ、使えなければ、理由を知らせて終わる
  (`HEIRAN_SKIP_OPENGL_CHECK` で、省ける)。
  **見直す条件**: GPU の無い環境での利用 (仮想マシン、CI) の要望が出たとき (`opengl32sw.dll` を、別の配布物にする)。
- **VC++ ランタイムは同梱せず、インストーラが案内する**: `vc_redist.x64.exe` (約 19 MB) は、圧縮済みで LZMA にかけても縮まず、パッケージの作成の時間だけ余計にかかる。
  DLL を直接同梱する案 (アプリローカル配布) は、セキュリティ更新が届かない、Qt の DLL と版がずれる、などの欠点があるため採らなかった。
  インストーラは、レジストリ (`HKLM\SOFTWARE\Microsoft\VisualStudio\14.0\VC\Runtimes\x64`) の `Installed` / `Major` / `Minor` を読み、
  **ビルドに使った CRT ヘッダの版以上** (`crtversion.h` が 14.51 なら、ランタイム 14.51) が無いとき、Microsoft の配布ページ (`aka.ms/vs/17/release/vc_redist.x64.exe`) を開くかを尋ねる。
  開かなくても、インストールは続ける。サイレントのときは、尋ねない。ランタイムは新しい版が古いビルドと互換のため、最新の版を入れればよい。
  ZIP の利用者には、README と手引きで、要件として書く。**見直す条件**: 案内だけでは、起動できない利用者が多いとき (インストーラが、ダウンロードして実行する)。

### 起動時のフォント初期化

- **決定**: アプリのフォントを値でコピーし、`QFontMetrics` の初回文字幅計算をワーカースレッドで実行する。
  UI スレッドでは OpenGL の対応確認を進め、両方が完了してから主ウィンドウを構築する。
  `QFutureSynchronizer` で待つため、OpenGL 非対応で早期終了しても、Qt の終了後までタスクを残さない。
  ウィジェットの作成と操作は UI スレッドに保つ。
- **理由**: 最近の画像一覧の文字幅計算で初回フォント初期化が発生し、OpenGL の確認と直列に待っていたため。
  コピーしたフォントと [再入可能な QFontMetrics](https://doc.qt.io/qt-6/qfontmetrics.html) のみをワーカーで使う。
  Windows / clang-cl / Qt 6.11.1 / Release、画像なしの起動を交互に 7 回ずつ測り、初回を除いた 6 回で比較した。
  `main()` 開始から初回フレームまでの中央値は直列 583.61 ms、並行 471.99 ms (約 19% 短縮)。
  プロセス作成から同じログを受信するまでの中央値は直列 599.63 ms、並行 488.42 ms。
  後者の最小 / 最大は直列 593.61 / 604.54 ms、並行 482.06 / 494.72 ms。
  計測は `py tools/benchmark_startup.py --compare --runs 6`。キャッシュが温まった同一環境の比較であり、初回起動の保証値ではない。
- **見直す条件**: Qt やフォント環境の変更で並行初期化の効果がなくなる、または初期化の競合が確認されたとき。

### CMake 入力の変更をビルドへ反映する

- **決定**: CMake の自動再構成を有効にする。ソースの追加や翻訳・リソースなど CMake 入力の変更を、通常のビルドで反映する。
  コンパイラや Qt、ビルド構成の変更は、明示的な configure で行う。
- **理由**: 自動再構成を無効にすると、追加ソースが古いビルド定義から抜けたままになり、未解決シンボルや変更の未反映を起こすため。
- **見直す条件**: 自動再構成が繰り返されるなど、具体的な不具合が確認されたとき。

### インストーラーによる更新

- **決定**: 起動時の旧版アンインストールを無効にし、同じインストール先への上書きで更新する。
  ［インストール］を押す前のキャンセルでは既存版を変更しない。ファイルコピー開始後の更新は、旧版への自動復元を保証しない。
  新版に含まれない旧ファイルは自動削除せず、将来、削除が必要になった場合は対象を限定した移行処理を設ける。
- **理由**: ウィザードを開いただけで旧版を削除すると、途中でキャンセルした場合にアプリが使えなくなる。
  配布対象の実行ファイルと DLL は上書きでき、更新のための事前アンインストールは必須ではない。
  インストール先を一括削除すると利用者が置いたファイルまで消すおそれがあるため、不要ファイル対策としても採らない。
- **見直す条件**: 配布ファイルの構成変更で旧ファイルが動作へ影響するとき、または更新失敗からの自動復元が必要になったとき。

### インストーラーの外観

- **決定**: CPack / NSIS 標準のページ構成を保ち、歓迎・完了画面には暗いサイドパネルと既存のアプリアイコンを置く。
  操作部分は標準の明るい UI と Segoe UI を使い、各ページの右上にも同じアイコンを置く。
  画像は 3 倍の画素数で生成し、DPI-aware を有効にする。生成済みの BMP をビルド入力としてコミットする。
  `appearance.nsh` を配布物とインストール処理のない画面プレビューで共有する。
  独自の確認文と構成要素の名前・説明は NSIS の言語リソースへ分離し、日本語と英語に対応する。
  構成要素を選ぶ標準ページは「ファイルの関連付け」として案内し、各項目名にも関連付けの設定であることを明記する。
  対応する画像形式は、関連付けの選択にかかわらずすべて利用できることをページの説明に示す。
  関連付けはインストールコンポーネントから分離した NSIS のセクションで扱い、カテゴリと拡張子を明示的な順序で作る。
  画像カテゴリは既定で全選択とし、拡張子一覧を選択肢・登録対象・削除対象で共有する。関連付けページだけ容量の表示を消す。
  CPack のテンプレート全体を複製せず、configure 時に旧版削除メッセージ・対応言語・関連付けページの案内に必要な部分だけを調整する。
  該当する文や言語ブロックが見つからなければ、無言で英語へ戻さず configure を失敗させる。
- **理由**: Heiran の控えめな配色とアイコンで製品を識別でき、標準 UI のキーボード操作や多言語表示を維持できる。
  通常のビルドに画像生成の依存を増やさず、既存のインストール環境を変更せずに外観を確認できる。
  CPack の標準文だけが英語のまま残ることを防ぎ、アップグレードや関連付けの処理は標準のまま維持する。
  画像形式への対応を追加インストールする選択肢だと誤解されないようにする。
  関連付けに無関係なダミーファイルを配布せず、個別に外した拡張子がまとめて登録されることを防ぐ。
- **見直す条件**: 標準ページでは収まらない案内や、独自のインストール手順が必要になったとき。

## 画面の文言の翻訳

- **Qt Linguist (`tr` と `.ts`) を使う**: コードの文言は英語で書き、日本語は `resources/i18n/heiran_ja.ts` に持つ。`.qm` は、実行ファイルへ埋め込む (配布物のファイルが欠けても、日本語で出る)。
  言語は、OS の表示言語に従う (対応していなければ英語)。設定の Language で、`System` / `English` / `日本語` を選べる。**切り替えは、次の起動から効く** (メニューなどの文言を、作り直さずに、その場で替える仕組みは、見合わない)。
  `HEIRAN_LANGUAGE` で、設定に関わらず上書きできる (確認用)。
  - **試験は、翻訳を読み込まない**: 試験が、メニューの項目を、英語の文言で探すため。翻訳の抜けと、`%1` の番号の食い違いは、`.ts` を読む試験 (`heiran_localization_tests`) で見る。
  - **範囲**: 画面の文言 (`src/ui`、`src/app`、`src/main.cpp`) を翻訳する。デコーダー (`src/infra`) の診断メッセージは、ライブラリの文言とファイルの経路を含み、報告のときに、英語の方が使いやすいため、英語のまま。
    画素値の読み取りのチャンネル名 (Gray / Red など) も、短い技術的な表示のため、英語のまま。マニュアルは、日本語だけ (英語版は、要望が出たとき)。ただし、メニューやボタンの名前は、日本語の表示の名前で書き、英語の名前を添える。画面の画像は、日本語の表示で撮る (英語の本文を、保守するより、読み替えの手間を減らすことを選んだ)。
  - **同じ英語は、同じ訳**: 同じ英語の文言が、複数の場所にあるときは、同じ訳を使う (`.ts` を、文言ごとに 1 つの訳で作ってある)。文脈で訳を変える必要が出たら、`tr` の曖昧さ回避の引数 (`disambiguation`) を使う。
  - **アイコンの対応**: アクションのアイコンは、文言から引く (`ActionIcons`)。翻訳された文言でも引けるように、鍵に翻訳後の文言も入れている。
- **見直す条件**: 英語、日本語のほかの言語の要望が出たとき (`.ts` を足す。`resolveLanguage` の対応言語を増やす)。起動し直さずに切り替えたい要望が出たとき (`QEvent::LanguageChange` を受けて、文言を付け直す)。

## 開発の進め方で得た教訓

- **測ってから直す**。重いと感じた場所は、思い込みと違うことが多い (先読みを広げる前に OpenGL コンテキストの生成が律速と分かった、
  間引きデコードは PNG で逆効果だった、など)。内訳を測り、**待っていない計測、手が止まった区間を含む計測は、速いという結論を作る**。
- **ビルドが途中で失敗したら、クリーンビルドからやり直す** (新旧のオブジェクトが混ざって構造体の配置が食い違い、間欠的な
  アクセス違反になる)。
- **テストは、壊して確かめる**。落ちない回帰テストは意味が無い。`QSKIP` は終了コード 0 になるため、通ったことだけでは検証にならない。
  GPU の出力は、CPU の実装と突き合わせる (オフスクリーンのフレームバッファ)。
- **Qt の落とし穴**:
  - `QColorSpace::primaryPoints()` の戻りは、項目が 1 つ分ずれて返る (Qt 6.11.1)。比較は `QColorSpace` どうしの `==` で行う
    (挙動を固定するテストがあり、Qt が直ると落ちる)。
  - `QScreen::name()` は Windows で GDI の装置名ではなく、モニタの表示名。
  - `QPainter::viewport()` はデバイス座標を返す (論理座標の `rect()` と取り違えると、devicePixelRatio が 1 でない画面でずれる)。
  - `QImage::scanLine()` の非 const 版は detach を通る。並列に呼ばない。
  - `QOpenGLWidget` の `repaint()` では `paintGL` が走らない。
  - `moc` は、ダブルクォートの中の `/*` をコメントの開始として扱う (`Q_OBJECT` を見つけられず、`metaObject` の未解決になる)。
  - `qDebug()` の出力をファイルへリダイレクトすると、何も書かれない (`QT_ASSUME_STDERR_HAS_CONSOLE=1`)。
  - `QTest` は事象の輪を回さない。スレッドを持つものは、`aboutToQuit` ではなく `qAddPostRoutine` で畳む。
- **Windows の落とし穴**: NSIS では `;` がコメントの開始 (説明文に入れると、そこ以降が消える)。`.rc` が参照する `.ico` は
  ビルドシステムから見えないため、`OBJECT_DEPENDS` で依存を明示する。

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| OpenImageIO で全形式を読む | 依存が重く、ビルドが遅く、黙って無効になる機能があった。形式ごとのライブラリを直接使う |
| Wuffs の PNG デコーダ | Qt と同等で優位が無く、16bit に非対応 |
| HEIC (libheif / libde265) | HEVC の特許、LGPL / GPL の依存、攻撃面。必要になったら WIC を呼ぶ |
| 間引きデコードをビューアで使う | PNG で逆効果。現在ページも先読みも元の解像度が要る |
| 解析用バッファを常に `float32` にする | 8bit を広げても情報が増えず、メモリが 4 倍になる |
| 浮動小数画像の最大値による自動正規化 | 画像ごとに基準が変わり、比較にならない |
| 反転を最大値基準にする | 同上 |
| ヒストグラムの軸を最大の度数に合わせる | 山が動くたびに全体の高さが変わる |
| GPU テクスチャの上限をセル数で割る | 余る枠が出て、多いセルが使えない |
| APNG の差分保持 | 全面を置き換える実物ではメモリが減らない |
| GIF の貯める形式に LZ4 | 圧縮率が zstd より 1.4 から 2.5 倍悪く、速さに差が無かった |
| `QOpenGLWindow` への移行 | 画面の更新に揃わず、応答が悪化し、セルごとに native window になる |
| `DwmFlush` で vblank を待つ | 間隔が更新レートと一致しない |
| SIMD の手書き、解析の GPU 化 | 自動ベクトル化で足りる。結果の読み戻しで差が出ない |
| 色空間を `cells[]` に置く | 同じ画像が 2 つのセルで別の色空間になる |
| 解析値の空間に `display` | どの画面のプロファイルで測ったかが数値に付いて回る |
| 差分のセルから、さらに差分を取る | 参照が循環する。元は常に画像のセル |
| CPU で working space へ正規化する | 元の値を書き換え、解析が元の値を読む契約が崩れる |
| Windows のサムネイルを自前で提供する | WIC で足りる形式が多く、独立した DLL の運用が重い |
